# NCM Gapless

让网易云音乐桌面客户端更连贯地播放连续专辑。

像 The Weeknd 的《Dawn FM》这样的专辑，曲目之间的衔接本身就是作品的一部分。NCM Gapless 尝试提前准备下一首，并让两首歌曲在同一个音频时钟上相接，减少切歌时加载和重新启动带来的中断。

**当前版本：`0.2.1-experimental`。当前可运行实现面向 Windows；macOS 版已列入路线图，尚未实现。** 项目名不绑定操作系统，后续按平台增加适配器。

## 目前能用到什么程度

| 项目 | 当前状态 |
| --- | --- |
| 网易云客户端 | 已实测 `3.1.42.205594 x64`，未知版本会拒绝启用 |
| 系统 | 已实测 Windows build `26200 x64` |
| 启动方式 | Windows 自带 PowerShell 5.1；另测过 PowerShell 7.6.6 |
| 连续播放 | 已接入真实播放链路，完成自然换歌回录和实际试听 |
| 播放控制 | 已验证暂停、恢复、定位，以及停用后恢复官方播放 |
| 其他 Windows 版本 / 架构 | 尚未完成实机兼容性验证 |
| macOS | 规划中，需要单独研究客户端和输出链路 |

这仍是实验项目。目前的结果只覆盖上述客户端和测试环境，不能据此承诺兼容所有网易云版本、设备或音效。

## 开始使用

从本仓库下载源码 ZIP 并解压，或克隆仓库。保留文件的目录结构，然后在 Windows 上：

1. 双击 `Start-NcmGapless.cmd`。若提示无法连接现有网易云实例，完全退出网易云，再运行启动器。
2. 在网易云中重新选择一首歌曲开始播放。启用时已经播放的歌曲可能仍由原生播放器处理，接管从下一次重新选曲开始。
3. 双击 `Get-NcmGaplessStatus.cmd` 查看状态。
4. 需要停用时，双击 `Stop-NcmGapless.cmd`。

运行补丁不需要 Python、Node.js 或管理员权限。关闭并重新打开网易云会清除内存中的补丁；之后需要再次通过启动器启用。

非标准安装路径可以手动指定：

```powershell
.\Start-NcmGapless.ps1 -ClientPath 'D:\Apps\CloudMusic\cloudmusic.exe'
```

状态中的几个关键字段：

| 字段 | 含义 |
| --- | --- |
| `version` | 当前内存中加载的补丁版本 |
| `installed: true` | 补丁已启用 |
| `active: true` | 当前曲目已由实验引擎接管 |
| `playing: true` | 实验引擎正在播放 |
| `nextReady: true` | 下一首已完成预取、解码和预排 |
| `fallbacks` / `lastError` | 回退次数和最近一次错误代码 |

`installed` 不代表当前曲目已接管，`nextReady` 也不能单独证明实际输出没有卡顿。

### 更新与停用

从旧版更新时，先运行 `Stop-NcmGapless.cmd`，再运行新版 `Start-NcmGapless.cmd` 并重新选曲。重复运行启动器不会替换仍然驻留在内存中的旧版。

启动器不改写网易云安装文件，通过仅监听本机回环地址的调试接口加载脚本。批处理中的执行策略参数只作用于当次 PowerShell 进程，不修改系统执行策略。

## 工作原理

项目保留官方选曲、账号权限、队列和歌词流程，在受支持的播放加载入口接入实验音频引擎。

```mermaid
flowchart LR
    A[官方选曲与权限检查] --> B[获取当前及下一首播放信息]
    B --> C[读取授权音源并提前解码]
    C --> D[同一 AudioContext 预排相邻音源]
    D --> E[连续输出]
    D --> F[向官方界面反馈进度和结束事件]
```

实现分为五个环节：

1. **发现并验证客户端接口。** 按客户端版本和接口能力查找官方 SDK、播放状态和预取入口，避免依赖固定进程地址或写死模块编号。
2. **准备合法可播放的音源。** 使用官方返回的播放信息和已有权限；链接失效时调用官方的同曲目、同音质刷新流程。读取或格式不满足要求时回退官方播放。
3. **校验解码后的有效长度。** 对受支持的单音轨 AAC/M4A 布局，核对样本时长表、编码延迟和编辑时长，修正可确定的容器时基精度问题。音频包保持原样；无法确认的布局不猜测裁切。
4. **提前安排下一首。** 当前曲目结束前，下一首已经解码，并安排在同一个 `AudioContext` 中当前音源的结束时间。音频衔接依靠共享时钟；`ended` 回调用于通知官方业务流程。
5. **保持官方状态同步。** 向客户端反馈加载、播放、进度、暂停、定位和结束，并取消失效的预排任务。

因此，项目不会通过检测低音量、跳过音乐中的静音或提前按“下一首”来模拟无缝，也不使用交叉淡化去重叠两首歌。

### 为什么 0.2.1 修复了第二首开头的停顿

第一版虽然把两首安排在相邻时刻，但官方客户端在第二首加载后会再次下发当前倍速。补丁曾把重复的“1 倍速”也当作重新定位，停止已经播放的第二首，再启动音源。

这个问题在声卡回录中产生了约 **100.6 毫秒**的额外停顿。0.2.1 对相同倍速直接返回，避免重启当前音源。对应离线回归用例修复前失败、修复后逐采样误差为 0；真实自然换歌回录也不再测得这次额外停顿。

## 验证结果

截至 2026-10-26，已保留下列测试记录：

| 验证层次 | 结果与边界 |
| --- | --- |
| CEF 离线渲染 | 8 项核心检查，覆盖 44.1 / 48 / 96 kHz 连续信号、保留原有静音和错误接缝对照 |
| 编码与解码 | 16 项生成 FLAC、MP3、AAC 检查；AAC 与 FFmpeg 解码参考最大误差约 `1.2e-7` |
| 实际播放引擎与 SDK 契约 | 7 项检查，包括第二首播放中重复设置相同倍速的回归用例 |
| 官方控制与恢复 | 暂停、恢复、暂停时定位、停用恢复，以及 Windows PowerShell 5.1 冷启动 |
| 真实输出 | 0.2.1 的 Dawn FM → Gasoline 自然衔接回录通过，无定位、暂停或变速；未测得额外插入时间 |

回录分析网格为 **0.125 毫秒**，参考与回录波形统一带限后比较，相关度均超过 0.998；结果仅覆盖所测设备与衔接。音频只在本机内存中处理，仓库不包含歌曲文件。

0.2.0 曾通过调度和状态同步检查，随后仍被实际试听发现声音中断。这次排查说明：排程间隙为 0、界面进度正常，都不足以证明声音连续。因此本项目将离线渲染、官方状态交接、声卡回录和实际试听分别记录。

详细过程见 [实现与验收记录](docs/implementation.md)，修复前后对照见 [0.2.1 回录证据](docs/evidence/handoff-v0.2.1.json)。[首轮研究记录](docs/feasibility.md)保留了当时的失败结果，应按其中的时间边界阅读。

## 已知限制

- 首次选曲需要完整缓冲当前曲目；解码缓冲预算为 256 MiB。长音轨、网络失败或超出预算时可能回退。
- 当前支持具有有效播放信息的 MP3、FLAC、WAV，以及通过严格时长检查的单音轨 AAC/M4A。真实专辑验收主要使用官方提供的 AAC/M4A；其他格式的证明主要来自生成样本。
- 部分 AAC 布局只有粗粒度编辑时长，且缺少可确定的尾部有效采样数，会报 `AAC_INTENTIONAL_EDIT_UNSUPPORTED` 并回退。该问题仍待处理，相关曲目不保证无缝。
- 只有加密本地缓存路径、试听或其他权限不满足的音源不接管。项目不提供会员或版权限制绕过、缓存解密或替代音源。
- 实验引擎尚未复现官方原生音效链。空间音频、特殊增强音质、独占设备、蓝牙、系统媒体控制和混合采样率播放仍需单独验收。
- 随机播放、单曲循环、动态修改队列、切换音质或设备等复杂场景尚未完整覆盖。

## 后续计划

| 优先级 | 方向 | 完成标准 |
| --- | --- | --- |
| P0 | AAC 时长布局与回退状态 | 扩展有依据的兼容范围，保留失败对照；不靠猜测裁切音频 |
| P0 | 稳定性与验收工具 | 连续多次自然换歌、输出回录与控制操作均有可复现结果 |
| P1 | Windows 兼容矩阵 | 按系统、架构、客户端版本分别完成实机验证 |
| P1 | macOS 可行性验证 | 在真实 Mac 上确认客户端接口、音源读取和音频输出链路 |
| P2 | macOS 实验版本 | 完成启用、停用、状态同步与自然换歌回录，分别验证 Intel / Apple Silicon |
| P2 | 发布与维护 | 自动化可离线检查、版本适配、可校验便携包和贡献流程 |

macOS 的启动与客户端适配需要独立实现；现阶段不假定它与 Windows 使用相同内核或桥接接口。可复用的候选部分是 AAC 时长处理、音频调度核心和验证方法。

详细任务与验收条件见 [路线图](docs/roadmap.md)，版本变化见 [CHANGELOG](CHANGELOG.md)。路线图表示计划，不构成已支持平台清单。

## 开发与贡献

```text
src/                     音频核心、AAC 时长处理与客户端适配
tests/                   离线音频与回录分析回归用例
tools/                   启动、打包、检查与开发诊断工具
docs/evidence/           不含账号或音源内容的验证记录
```

贡献前请阅读 [CONTRIBUTING](CONTRIBUTING.md)。开发验证需要 Python、FFmpeg 和 `requirements-dev.txt` 中的依赖；便携运行不需要这些依赖。

```powershell
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -p "test_*.py" -v
python tools\verify_audio.py
python tools\verify_integration.py
python tools\build_portable.py
```

`verify_audio.py` 和 `verify_integration.py` 需要已连接的目标客户端，默认调试端口为 9222，其他端口用 `--port` 指定。生成的本地报告和便携 ZIP 分别放在 `.local/` 与 `artifacts/`，不会提交到 Git。

反馈问题时，提供系统与客户端版本、补丁版本、可复现步骤及脱敏状态即可。请勿上传 Cookie、令牌、音源地址、请求头值、歌曲音频或包含个人信息的原始日志。

本项目是独立实验项目，与网易云音乐没有官方关联。项目许可证尚待维护者确定。
