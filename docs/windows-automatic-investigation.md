# Windows 全入口自动启用：未通过验收

日期：2026-10-28。目标客户端：Windows x64，网易云 `3.1.42.205594`。

本轮研究的后台助手方案尚未通过验收，已撤销当前用户的登录启动项并停用助手，运行文件恢复为主分支的手动启动方式。实验代码仅保留在本机 `.local/windows-automatic-prototype/`，不进入运行包。

## 已观察到的结果

- 新增的 13 项离线生命周期检查在 Windows PowerShell 5.1 和 PowerShell 7 上通过；检查使用可控进程与 CDP I/O，不能证明真实客户端稳定。
- 实测曾从原桌面图标、开始菜单和直接运行程序成功加载补丁；完全关闭时也曾确认不会被助手主动重开。
- 后续真实停止 / 重开回归中，Windows Restart Manager 返回 `ERROR_FAIL_SHUTDOWN`（351），出现无窗口残留进程。
- 用户报告 `cloudmusic.exe` 的 `unknown software exception (0x80000003)`，位置为 `0x00007FF987E9A7F4`。目前没有足以定位调用栈的客户端转储或模块证据，不能仅据此确认崩溃根因。
- 等待原实例的子进程退出后仍再次出现失败。因此不能将退出清理竞争认定为已解决的根因，也不能交付这个自动重开方案。

## 已执行的恢复

- 撤销自动启用资格，等待助手退出，移除本轮创建的登录启动项。
- 恢复本轮修改的运行脚本、说明与打包清单；移除不合格的自动启用入口，保留隔离的本机实验副本。
- 核对三个网易云安装文件与三个原快捷方式的 SHA-256，未发现改动。

暂时继续通过 `Start-NcmGapless.cmd` 手动启动并加载补丁。Windows 任意入口直接启动后自动加载仍未实现；后续应先找到受支持的启动时加载方式或稳定的客户端退出路径，再开展新的实机验收。真实登录、文件关联与协议入口也没有完成独立验收。
