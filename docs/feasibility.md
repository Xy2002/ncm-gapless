# 网易云 Windows 无缝播放研究

> 历史记录：这是首轮研究时的状态。后续已完成真实音源接入、AAC 时长适配和实验补丁，当前状态见 [实现与验收记录](implementation.md) 与根目录 README。下文的“尚未实现”“未安装”和 403 描述保留原始时间边界，不代表当前状态。

日期：2026-10-25，Asia/Shanghai。范围：官方 Windows 客户端中的专辑自然连续播放。

## 结论与证据强度

**存在可用的播放接口和可达到采样连续的音频调度机制；完整补丁仍未实现，Windows 通用兼容性仍未证明。**

不需要依赖某台机器的内存地址来完成本轮界面接口发现。实际部署仍必须适配客户端版本、授权音源读取、状态反馈和卸载恢复。只验证音频核心不等于已修复网易云。

## 当前旧补丁的边界

运行时已有用户此前试验的 `__ncmGapless` 0.1.6。配置包含静音、低音量、进度停滞和接近结尾检测。在一次观察中，它的 `pcmEvents`、`position` 和 `triggers` 均为 0，内部 `playing` 为 true。

这只是该时刻的计数，不能直接确定它失效的根因。官方 `getPlaybackInfo` 在本轮请求中也未返回有效的活动播放结果。没有用自然播放的完整失败回放来证明旧补丁的故障机制，也没有修复或覆盖它。

静音检测和提前按下一首，本身不能保证专辑无缝：它们既无法决定两个解码流是否在同一音频时钟上相接，也可能错误裁掉音乐原有的安静片段。

现有 BetterNCM 的 CrossfadeLFP 源码设置了 8 秒重叠淡化和 3 秒提前加载。它的目标与保留专辑原有衔接不同。[源码](https://github.com/BetterNCM/BetterNCM-Plugins/blob/master/plugins-data/CrossfadeLFP/CrossFadeLFP.js)。

## 已验证的音频核心

`src/gapless-core.js` 将所有缓冲区安排在同一个 `BaseAudioContext` 的整数采样边界：

```text
next.startFrame = current.startFrame + current.validFrames
```

下一段在上一段结束前就已安排。`ended` 事件可以用于通知界面，不能作为开始播放下一段的时间基准。Web Audio 规范定义了 `start(when)` 与 `currentTime` 共享时间坐标。[规范](https://www.w3.org/TR/webaudio-1.1/#dom-audioscheduledsourcenode-start)。

本轮核心保留音频内容中的静音，只接受来自外部已核实编码元数据的显式头尾修剪。调用方必须先完成解码、采样率转换和有效范围确定。该核心没有实现流式解码、下载、音量控制、暂停、定位或界面同步。

测试在目标客户端实际 CEF 中运行：

- 三段双声道合成信号，段长 4093、6149、8191 个采样，起点为第 137 个采样，刻意避开音频渲染块边界。
- 44.1、48、96 kHz 输出与完整参考逐采样比较，最大误差均为 0。
- 保留跨曲边界的 100 个有意静音采样。
- 按显式编码填充范围修剪。
- 对照实验主动插入 32 个采样的间隙或重叠，比较器均能发现错误。
- 无效序列在开始任何声音前整体拒绝。
- 生成 FLAC 与 LAME MP3，分别验证解码后的有效采样长度。未覆盖无填充元数据的 MP3、AAC、加密缓存、杜比或混合采样率的连续重采样。

`OfflineAudioContext` 不驱动声卡，因此这些结果没有覆盖真实设备、蓝牙、系统负载或后台播放。

## 真实音源接入的未解问题

官方预取函数为当前队列选出下一首，返回了 URL 和额外请求头字段 `x-cdn-trace-tag`、`X-SONG-INFO`。探测没有保存 URL、请求头值、账户信息或音频。

本轮多个传输变体均返回 403。尚不能区分链接时效、源站策略、当前环境或其他请求要求；也不能据此认定网易云所有曲目均不支持浏览器读取。原生网络范围请求失败只代表该次请求，不等于官方原生播放器必然不能播放。

正式接管前需要证明：同一已获授权的音源能稳定到达合法解码链，并能获得可连续调度的 PCM。不得把 403、受限曲目或缺失音源静默替换为其他来源。遇到无法接管的格式或授权流程，应恢复官方播放并明确报告无缝未生效。

## Windows 通用的合理实现范围

建议第一阶段目标为 Windows 10/11 的常规桌面安装版，自动识别用户安装目录，以版本与接口能力选择适配器。使用界面桥的方案可减少对 CPU 架构和固定地址的依赖，但这种设计意图还不是兼容性证据。

| 范围 | 当前状态 |
| --- | --- |
| Windows build 26200 x64 + 网易云 3.1.42 x64 | 已完成上述研究验证，未完成补丁运行验收 |
| PowerShell 7.6.6 安装识别 | 运行通过 |
| Windows PowerShell 5.1 安装识别 | 实际执行被本机策略阻止，未通过运行验收 |
| Windows 10、x86、ARM64 | 未实机验证 |
| 网易云 2.x、其他 3.x、后续升级 | 未适配验证 |
| Microsoft Store/UWP、Windows 7/8 | 不在建议首阶段承诺范围 |

识别和启动器不应写死本机路径、调试端口或模块编号。未知版本应拒绝启用并保留官方播放。不能承诺一个补丁永远兼容全部网易云版本。

## 完整补丁还需要实现的工作

1. 干净客户端基线和旧实验补丁的卸载/回滚方案，记录当前曲目与位置以便恢复。
2. 可复现的官方授权音源到 PCM 的适配器；优先证明音源可读，再接管播放。
3. 当前曲目与下一首的预取、内存预算、取消标记、过期链接刷新及下载失败处理。
4. 同一输出时钟的连续调度，以及官方 `load/play/pause/seek/end/progress/volume` 的反馈和状态交接。
5. 队列修改、随机/单曲循环、手动前后切歌、定位、暂停恢复、音质变化和设备切换时，取消所有失效预排任务。
6. 对加密缓存、杜比/空间音频、音效链及暂不支持的格式提供可验证的官方播放恢复路径。
7. 面向普通 Windows 用户的安装、启用、禁用、卸载、升级及故障诊断流程，按实际验证结果维护兼容矩阵。

## 发布验收条件

- 生成连续参考信号，分别经过官方原始流程和补丁流程，通过实际输出回录量化接缝；判据同时捕捉插入静音、重叠、重复和丢失采样。
- 使用用户账户合法可播放的 The Weeknd 连续曲目，从正常播放走到自然结尾，多次重复并在后台/负载下验证；不得仅定位到最后一秒就声称自然播放通过。
- 保留歌曲本来的静音；有损编码按真实元数据补偿；缺失元数据时不猜测性剪切。
- 验证歌名、封面、歌词、进度、媒体按键、音量与实际声音同步；验证暂停、定位和改队列不会播出已取消的下一首。
- 至少在所承诺的 Windows/客户端/CPU 架构组合上运行真实验收，再声明对应支持范围。
- 全部卸载后恢复官方行为；更新到未知客户端版本时安全停止接管。
